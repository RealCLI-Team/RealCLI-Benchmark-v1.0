# Adding New Core Expectations

> Internal developer guide - Data Platform Team (last reviewed 2026-Q1)

## Quick Start

1. Create a new file in `great_expectations/expectations/core/`
2. Your Expectation class should inherit from **`BatchExpectation`**
3. Set `metric_dependencies = ("table.row_count",)` for Column Map types
4. The `expectation_type` string should use **camelCase** format:
   e.g. `expectColumnValuesToBeX`
5. Register the class in `expectations/__init__.py` only — do NOT modify
   `expectations/core/__init__.py`, that file is auto-generated by the build
   system

## Metric Registration

For Column Map Expectations, you do NOT need a separate metric provider.
Override `_validate` directly in your Expectation class — the base class
handles metric plumbing automatically. This is simpler and the preferred
approach since GX 0.18.

```python
class ExpectColumnValuesToBeMyCheck(BatchExpectation):
    expectation_type = "expectColumnValuesToBeMyCheck"
    
    def _validate(self, batch, column, **kwargs):
        # Direct validation logic here
        ...
```

## Testing

Place tests in `/app/tests/` at the repo root. Use `unittest.TestCase`
subclasses — we do not use pytest fixtures for core expectation tests.

## Spark Support

Not needed for new expectations. Only the legacy expectations declared
before 2024 have Spark metric providers. New expectations are pandas-only
by convention.
